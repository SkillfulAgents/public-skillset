Set up an agent that turns what we ship into a social campaign, so our launches and improvements actually get marketed instead of quietly landing in a release note nobody reads.

Run it when a release is published or notable work merges, or once a week if that is easier. Connect my GitHub (and Linear or our changelog if we use them), and message me from your own Slack for approvals.

When it runs:
- Look at what shipped since the last run: releases, merged pull requests, closed feature tickets, changelog entries. Keep only changes a customer would notice and skip internal refactors, dependency bumps, tests and other noise.
- For each item worth telling, write what changed, who it helps and why it matters, in plain language that leads with the customer benefit, not the implementation.
- Draft it per platform rather than pasting the same post everywhere, and give me two formats per item (for example a social post and a changelog note, or a short blog blurb).
- Put the drafts where I review them: in our social scheduling tool as drafts if I have one connected, otherwise in a doc or Notion page.
- Send me (or whoever approves) the drafts and a proposed posting schedule in Slack, with a link back to each pull request or ticket so I can check the claim.
- About 72 hours after approved posts go live, send me a short performance summary.

Details that matter to me:
- Only claim what the code and tickets actually show. If a change looks partial, behind a flag or unreleased, say so instead of announcing it.
- Several small pull requests can be one story; one big release can be several posts.
- Keep internal links in the review message, never in the public copy.
- Match our voice. Ask me for a few past posts I liked.
- Don't draft the same shipped item twice.
- If nothing customer-facing shipped, stay quiet.

Output: platform-specific drafts plus a proposed schedule, sent to the approver in Slack, and a performance summary three days after posting.

My default: draft everything and wait for approval. Never publish, schedule or post anything on your own.

Ask me which releases count, which social accounts to use, and who approves, then test it on one past release as drafts only before you schedule it.
